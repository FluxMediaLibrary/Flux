## Architecture

### Account vs Profile

- **User (account)**: the login. Holds email, password, and role (`ADMIN` / `MEMBER`). Owns one or more profiles.
- **Profile**: Netflix-style sub-profile under an account. Watch progress, requests, and continue-watching all key off `profileId`.

JWT carries `sub` (accountId) + `role`. After selecting a profile, the token also carries `activeProfileId` for per-profile routes.

### Access control

| Route group | Guard |
|---|---|
| `/admin/*` | `role === ADMIN` on the JWT |
| `/profiles` | Logged in (any role) |
| `/(member)/*` | Logged in + active profile selected |
| `/(auth)/*` | Public (unauthenticated) |

Signup is invite-only: requires a valid, unexpired, single-use invite code generated by an admin.

### How media is joined

TMDb ID (`tmdbId` + `mediaType`) joins the library to requests. Library items are matched to TMDb at ingest. Requests use the same key so a fulfilled request automatically links to the matching library item.

### Playback

1. **Direct play** — serves the original file via byte-range endpoint. Works for browser-native codecs (MP4/WebM/H.264+AAC).
2. **HLS fallback** — on-demand FFmpeg transcode streamed through hls.js when the browser cannot decode the source.

Playback decisions are made per-file by probing codec support at the server level.

## Prerequisites

- Docker and Docker Compose
- [TMDb API key](https://www.themoviedb.org/settings/api) (v3, free)
- A domain pointed at your VPS (for frontend origin + invite links)
- At least 1 GB RAM free for transcoding

## Setup

### 1. Clone

```bash
git clone https://github.com/IDKDeadXD/Flux.git flux
cd flux
```

### 2. Configure environment

```bash
cp .env.example .env
```

Edit `.env` and fill in:

| Variable | Purpose |
|---|---|
| `TMDB_API_KEY` | TMDb v3 API key |
| `JWT_SECRET` | Long random string (`openssl rand -hex 48`) |
| `POSTGRES_PASSWORD` | Strong database password |
| `BOOTSTRAP_ADMIN_EMAIL` | Initial admin email |
| `BOOTSTRAP_ADMIN_PASSWORD` | Initial admin password |
| `FRONTEND_ORIGIN` | Public frontend URL (e.g. `https://flux.example.com`) |
| `NEXT_PUBLIC_API_BASE_URL` | Public backend URL (baked into frontend at build time) |

### 3. Start

```bash
docker compose up --build
```

On first run the backend applies pending Prisma migrations, then seeds the bootstrap admin account if no users exist yet.

### 4. Reverse proxy (nginx)

```
# Frontend — Next.js standalone
location / {
    proxy_pass http://127.0.0.1:4938;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

# Backend — Fastify API
location /api/ {
    proxy_pass http://127.0.0.1:6948;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

### 5. First login

Navigate to your frontend URL, sign in with the bootstrap admin credentials, then:

1. Create profiles via `/profiles`
2. Generate invite codes via `/admin/invites`

## Services

| Service | Image | Port | Public |
|---|---|---|---|
| Frontend | custom (`Dockerfile`) | 4938 | yes |
| Backend | custom (`Dockerfile`) | 6948 | yes |
| PostgreSQL | `postgres:16-alpine` | 5432 | loopback only |
| Redis | `redis:7-alpine` | 6379 | loopback only |
| Transmission RPC | `linuxserver/transmission` | 9091 | loopback only |
| Transmission peer | `linuxserver/transmission` | 51413 | TCP + UDP |

Transmission uses `network_mode: host` for correct peer port binding.

## Routes

### `/` (root)
Redirects based on auth state: unauthenticated → `/login`, logged in → `/home`, no profile → `/profiles`.

### Auth (public)

| Route | Description |
|---|---|
| `/login` | Sign in with email + password |
| `/signup` | Create account (requires invite code) |

### Member (requires profile)

| Route | Description |
|---|---|
| `/home` | Continue watching, recently added, genre rows |
| `/browse` | TMDb discover (trending, popular, genre filter) |
| `/library` | Library grid with type/genre/year filters |
| `/library/[id]` | Detail page (cast, episodes, play) |
| `/watch/[id]` | Video player (Plex-style UI) |
| `/profiles` | Profile selection and management |

### Admin (requires ADMIN role)

| Route | Description |
|---|---|
| `/admin/info` | System dashboard (uptime, storage, DB counts) |
| `/admin/torrents` | Upload .torrent files, manage downloads |
| `/admin/requests` | View and approve/reject media requests |
| `/admin/invites` | Generate single-use invite codes |
| `/admin/settings` | Notification config (Discord/SMTP) |

## API

REST/JSON under `/api`. JWT in `Authorization: Bearer <token>`. All input validated with Zod, all errors returned as `{ error, message, statusCode }`.

### Modules

| Module | Endpoints |
|---|---|
| Auth | `POST /api/auth/login`, `POST /api/auth/signup` |
| Profiles | `GET/POST /api/profiles`, `PATCH/DELETE /api/profiles/:id`, `POST /api/profiles/:id/activate` |
| Invites | `POST/GET/DELETE /api/invites` (admin) |
| Library | `GET /api/library`, `GET /api/library/:id`, `GET /api/library/:id/play` |
| Streaming | `GET /api/stream/:id`, `GET /api/stream/:id/hls/:file` |
| TMDb | `GET /api/tmdb/search`, `GET /api/tmdb/:type/:id`, `GET /api/tmdb/discover/*` |
| Requests | `POST/GET /api/requests` (per-profile), `PATCH /api/requests/:id` (admin) |
| Torrents | `POST/GET/DELETE /api/torrents` (admin) |
| Notifications | `GET/PUT /api/admin/notifications/settings` (admin) |
| Admin info | `GET /api/admin/info` (admin) |

## Data model

```
User ──< Profile ──< WatchProgress
  │                    │
  │                    ├──< Request ──< Torrent
  │
  ├──< Invite (created)
  └──< Invite (used)

MediaItem ──< Episode ──< WatchProgress
  │
  ├──< Torrent
  └──< WatchProgress

NotificationSettings (singleton)
```

| Model | Purpose |
|---|---|
| `User` | Login account (email, password, role) |
| `Profile` | Sub-profile under a user |
| `Invite` | Single-use, expiring signup code |
| `MediaItem` | Library entry matched to TMDb (movie or show) |
| `Episode` | Per-season, per-episode file for shows |
| `Torrent` | Download with status tracking and live stats |
| `Request` | Per-profile media request keyed to TMDb ID |
| `WatchProgress` | Per-profile save state (position, duration, completed) |
| `NotificationSettings` | Singleton for Discord/SMTP config |

## Development

```bash
# One-time setup
cp .env.example .env       # point DB/Redis at localhost
npm install
npm run prisma:generate
npm run prisma:migrate:dev

# Run locally
npm run dev:backend        # backend on :6948 (hot reload)
npm run dev:frontend       # frontend on :3000 (hot reload)
```

### Conventions

- TypeScript strict, ES modules, no `any` without explicit reason
- DTOs in `@flux/shared` — never redefine wire shapes on either side
- DB changes: edit `schema.prisma` then run `npm run prisma:migrate` (named migration)
- Path traversal protection: all media paths resolved against configured root
- Secrets: env only, never committed. TMDb key stays server-side
